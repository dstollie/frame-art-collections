# Frame Art collections

Community art collections for Samsung The Frame, consumed by the Frame Art Home Assistant add-on (github.com/dstollie/ha-frame-art). A collection is a JSON manifest in `collections/` that links to openly licensed images hosted elsewhere (Wikimedia Commons, museum IIIF servers). GitHub Pages publishes `index.json`, the manifests and the schema; there is no server and nothing is stored here but JSON.

## What we never compromise on

### 1. Only open licences

Every item is public domain, CC0, CC BY or CC BY-SA, and its `source_url` proves it. A work under NC, ND or an unclear licence never goes in, however beautiful. When in doubt, leave it out. CC BY works carry an `attribution` line.

### 2. Honest about AI

Generative-AI images are marked `"ai_generated": true`, come only from places with an explicit per-file licence (in practice Wikimedia Commons), and never depict real people or imitate a living artist. `knowledge/sources.md` records what was excluded and why; keep it current.

### 3. Made for the wall

The audience hangs these on a 4K panel. Favour recognised works, landscape format and ≥ 3840 px on the long edge. Thirty great works beat three hundred mediocre ones.

### 4. Polite to the sources

Scripts send a descriptive User-Agent, pace requests per host (`polite()` in `scripts/lib/http.ts`) and cache JSON responses in `.cache/`. Never parallelise requests against a museum API.

## A small glossary

- **you** means the coding agent reading this file.
- **collection** / **manifest**: one `collections/<id>.json` file. **item**: one artwork in it.
- **seed**: the collections generated by `scripts/seed.ts`; they carry `"generator": "scripts/seed.ts"`.
- **the app**: the Frame Art add-on, which reads `index.json` and the manifests.

## The ways to hurt yourself

1. **Hand-editing a generated collection.** `pnpm seed` overwrites it. Change `scripts/seed/defs.ts` (or `moods.ts`, `ai.ts`) and regenerate that collection with `pnpm seed --only <id> --no-moods`.
2. **Breaking the published contract.** The app reads `schema_version: 1`. Removing or renaming a field, or changing its meaning, is a breaking change: it needs a v2 schema next to v1.
3. **Trusting issue-form input.** `.github/workflows/issue-to-pr.yml` handles untrusted text. Pass it through files and environment variables, validate it in `scripts/issue-form.ts`, never interpolate it into a shell command or `${{ }}` expression inside `run:`.
4. **Hammering an API.** A full `pnpm seed` makes thousands of requests and runs for a long time on purpose. Use `--only` while iterating; the cache makes reruns cheap.

## Running locally

- Node 24 (see `.nvmrc`) runs the TypeScript directly; no build step. `pnpm install` once.
- `pnpm new …` creates or extends a collection from a list of Commons, Wikidata, SMK or Met references (`pnpm new --help`).
- `pnpm build` writes `dist/` exactly as Pages serves it.

## Verifying

- **When finishing a task, always run `pnpm check`** (typecheck, oxlint, oxfmt check, unit tests, validation).
- After adding or changing collections, also run `pnpm validate:urls collections/<id>.json` to load a sample of the images.
- Unit tests live next to the code as `*.test.ts` (node:test). Test behaviour, not wiring.

## Where code lives

- `schema/` – JSON Schemas for a collection (`collection.v1.schema.json`) and for the index (`index.v1.schema.json`). The source of truth for fields.
- `collections/` – the manifests.
- `scripts/validate.ts` – CI validation; rules in `scripts/lib/rules.ts`, URL sampling in `scripts/lib/urls.ts`.
- `scripts/new-collection.ts` – create or extend a collection from references; resolution in `scripts/lib/resolve.ts`.
- `scripts/seed.ts` + `scripts/seed/` – the seed generator: `defs.ts` (collections and their queries), `pipeline.ts` (gather, rank, select), `moods.ts` + `colour.ts` (colour collections), `ai.ts` (curated AI list).
- `scripts/sources/` – one module per source: `wikidata.ts`, `commons.ts`, `smk.ts`, `met.ts`.
- `scripts/build-site.ts`, `scripts/lib/index.ts` – the Pages output and `index.json`.
- `scripts/issue-form.ts` – issue form → `new-collection` arguments.
- `.agents/skills/add-collection/` – the skill that lets an agent add a collection end to end (`.claude/skills` is a symlink to `.agents/skills`).
- `knowledge/sources.md` – research on sources and licences, including AI art.

## Taste

- TypeScript strict, `erasableSyntaxOnly` (Node strips types: no enums, no parameter properties). Inferred types over annotations; no `any`.
- Short notation: `!list.length`, `!value`.
- No re-exports, import from the defining module.
- No code comments unless the code cannot say it; a one-line doc comment on an exported function is fine.
- oxlint and oxfmt decide style. Fix the code, don't disable the rule.
- GitHub Actions are pinned to a full commit SHA with the version in a comment.

## Commits and PRs

- [Conventional Commits](https://www.conventionalcommits.org) with a scope: `type(scope): Description`, e.g. `feat(collections): Add misty-mornings`, `fix(seed): Skip framed photos`, `docs(readme): Explain image_4k`.
- Small commits. Never push to `main` directly except for repository bootstrap; open a PR and fill in `.github/PULL_REQUEST_TEMPLATE.md`.
